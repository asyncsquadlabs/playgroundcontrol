Before you begin

Set up a safe test bench

This product installs a Windows service and closes configured processes. Use a disposable PC or VM, not a work machine or a machine with unsaved game progress.

Setup
!

Use a disposable Windows environment. Uninstall intentionally deletes the PIN, game list, audit history, service, and firewall rule. Enforcement can force-close configured applications after a 10-second grace period.

i

Two Windows roles are required for the realistic test: a parent/administrator account for installation and recovery, and a standard player account for the tamper-resistance check. Do not make the player an administrator if you want the documented guarantee.

You will need

  • Windows 10 or 11 x64 PC or VM with local administrator access.
  • A second device on the same private LAN: phone, tablet, or another PC.
  • A standard (non-admin) Windows player account for the privilege test.
  • The artifact dist/PlaygroundControl.exe and its SHA-256.
  • A test application already present on Windows. This guide uses notepad.exe and timeout.exe.
  • Time to reboot the PC once and to perform a destructive uninstall at the end.

P.1Essential2 min

Confirm the test PC is disposable and you are an administrator

Open an elevated PowerShell window and confirm elevation. The product installs a LocalSystem service and writes to Program Files and ProgramData.

PowerShell check 
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
  [Security.Principal.WindowsBuiltInRole]::Administrator
)
ExpectedTrue. If it returns False, relaunch PowerShell with Run as administrator.
P.2Essential3 min

Connect both devices to the same private LAN and note the PC address

The built-in firewall rule is inbound, TCP 8080, private profile, local subnet only. The Windows network profile must be Private, not Public.

http://192.168.1.50:8080
PowerShell: find the PC LAN address 
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.PrefixOrigin -ne 'WellKnown' } |
  Select-Object InterfaceAlias, IPAddress
Get-NetConnectionProfile | Select-Object Name, InterfaceAlias, NetworkCategory
ExpectedA private IPv4 address such as 192.168.1.50, and NetworkCategory = Private. Keep the phone on the same Wi-Fi/LAN and disable guest Wi-Fi client isolation if necessary.
P.3Essential1 min

Copy the EXE to the test PC and verify its SHA-256

From the project folder, transfer dist/PlaygroundControl.exe to a local folder such as C:\Tests. Do not run it from a network share. The expected hash is shown in the hero above.

PowerShell: verify the exact artifact 
Get-FileHash .\PlaygroundControl.exe -Algorithm SHA256 |
  Format-List Algorithm, Hash, Path

# Expected:
# 25d55e728f94cb221a40173c3af5bcde0516bc4e6dcdd51068eb6160d08d1ecb
ExpectedThe hash matches exactly. If it does not, stop and do not run the file.

Phase 1

Installation and service registration

Observe the first-run experience and prove that Windows received the service, firewall rule, uninstall entry, and protected data directory.

4 tests
01

Install and verify the service

UAC, SmartScreen, Program Files, SCM, firewall, and data ACL.

I.1Essential3 min

Double-click the EXE and approve the UAC prompt

SmartScreen may show Windows protected your PC because the test EXE is unsigned. If you verified the hash, choose More info, then Run anyway. Approve the administrator prompt. No separate installer framework or runtime is needed.

ExpectedThe installer completes without a console window. It copies itself to C:\Program Files\PlaygroundControl\PlaygroundControl.exe, starts the service, and opens a local first-run setup page in your default browser. If the browser does not open, see Troubleshooting.
I.2Essential2 min

Verify the service, listener, and firewall rule

Open an elevated PowerShell window and run the following. The service should run as LocalSystem, start automatically, and listen on TCP 8080.

PowerShell: inspect installed components 
Get-CimInstance Win32_Service -Filter "Name='PlaygroundControl'" |
  Select-Object Name, State, StartMode, StartName, PathName

Get-Service PlaygroundControl | Format-List Name, Status, StartType

Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalAddress, LocalPort, State, OwningProcess

Get-NetFirewallRule -DisplayName 'Playground Control' -ErrorAction SilentlyContinue |
  Select-Object DisplayName, Enabled, Direction, Action, Profile
ExpectedService Running, StartMode Auto, StartName LocalSystem. TCP 8080 is listening. Firewall rule enabled, inbound, allow, private profile. The EXE path points into Program Files.
I.3Essential1 min

Confirm the loopback health endpoint

The dashboard is served by the same EXE. Loopback health is intentionally local-only.

PowerShell: local health check 
Invoke-RestMethod http://127.0.0.1:8080/api/v1/health |
  ConvertTo-Json -Depth 3

# Expected shape:
# {
#   "ok": true,
#   "version": "1.0.0",
#   "setup": true
# }
ExpectedHTTP 200 with ok: true. If the first-run setup is still pending, setup is true; later it will be false.
I.4Advanced3 min

Verify the data directory is not readable by standard users

The installer applies an explicit ACL. Use an elevated PowerShell prompt and inspect the ProgramData directory. Standard users should not appear in the access list.

PowerShell: inspect files and ACL 
Get-ChildItem 'C:\Program Files\PlaygroundControl' -Force
Get-ChildItem 'C:\ProgramData\PlaygroundControl' -Force

icacls 'C:\ProgramData\PlaygroundControl'

# After setup, the following should exist:
#   auth.json, setup.token (until setup completes), service.log
# The ACL should show SYSTEM and Administrators, not BUILTIN\Users.
ExpectedProgram Files contains the EXE. ProgramData is accessible to SYSTEM and Administrators only. Standard users must not be granted access.

Phase 2

First run, PIN setup, and access rules

Prove that the initial PIN can only be claimed on the gaming PC, and that later LAN access requires authentication.

4 tests
02

Claim the administrator account

Local-only setup, numeric PIN, login, optional PIN change, and lockout.

A.1Essential2 min

Before creating a PIN, try the setup page from another LAN device

Do this immediately after installation, while the dashboard still says setup is required. On your phone, open http://<PC-LAN-IP>:8080/setup. This is the negative test: a phone must not be able to claim the administrator PIN.

ExpectedThe phone shows a message that initial setup must be completed on the gaming PC. It must not display a usable PIN form. Then return to the PC and complete setup locally.
A.2Essential3 min

Create the administrator PIN on the gaming PC

The setup page should be open at http://127.0.0.1:8080/setup?token=.... Choose 6 to 12 digits, confirm the PIN, and save. The token is one-time and expires after 15 minutes.

ExpectedThe setup succeeds, the setup token disappears from the URL, and the dashboard opens. The play state should say Play is blocked with no game configured yet. The PIN is never shown again.
A.3Essential3 min

Sign in from a second device on the LAN

On the phone, open http://<PC-LAN-IP>:8080. Try one incorrect PIN, then sign in with the correct PIN. The dashboard is responsive and should show the LAN URL and block state.

ExpectedThe wrong PIN is rejected. The correct PIN opens the dashboard. Browser traffic is HTTP on the private LAN, so do not use this over an untrusted or public network.
A.4Advanced5 min

Verify login throttling, then clear it with an admin service restart

From one device, enter a wrong PIN five times. The fifth attempt should trigger a temporary IP lock. The lock is held in memory; restarting the service as an administrator clears it without changing the PIN or game state.

PowerShell: clear the in-memory login throttle 
Restart-Service PlaygroundControl -Force
(Get-Service PlaygroundControl).Status
ExpectedAfter five failures, login is refused for roughly 15 minutes with HTTP 429 / a lock message. After the service restart, the correct PIN works again. All browser sessions are invalidated by the restart.

Phase 3

Core play enforcement

This is the heart of the acceptance test. First verify that Roblox is stopped before launch by the built-in guard, then use harmless built-in applications for the close and force-kill paths.

6 tests
i

Safety: the built-in Roblox guard is always active while play is off, even if Roblox has never been added to the custom list. Add only notepad.exe and timeout.exe to the custom list for this run. Do not add system processes such as explorer.exe, lsass.exe, or svchost.exe; the app rejects a known critical-process list, but the safe test is still deliberately small. Remember that settings persist across reboot.

03

Verify the flag actually decides whether games can open

Test the mandatory Roblox pre-launch guard, then add games, block, allow, revoke while running, and verify forced termination.

R.1Essential5 min

Roblox must not launch while play is blocked

Do not add Roblox to the dashboard: this guard is built in. With play blocked, close every Roblox window, then open Roblox from the Start menu, its desktop shortcut, or a Play button on the Roblox website. If Roblox is not installed, install it once while play is allowed, then return to blocked mode.

Elevated PowerShell: confirm Windows launch interception is armed 
'RobloxPlayerBeta.exe','RobloxPlayerLauncher.exe','RobloxPlayerInstaller.exe' | ForEach-Object {
  Write-Host "--- $_"
  reg.exe query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\$_" /v Debugger
}

# Expected Debugger value contains PlaygroundControl.exe and --deny-launch.
# The 32-bit registry view should have the same guard:
reg.exe query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\RobloxPlayerBeta.exe" /v Debugger
ExpectedRoblox does not open. A Playground Control message explains that Roblox is blocked while play is off, and Task Manager shows no new RobloxPlayerBeta.exe process. The IFEO entries exist in both registry views. Press Allow play, launch Roblox once, and confirm it opens. Press Block play again and confirm a fresh launch is intercepted.
E.1Essential3 min

Add Notepad while play is blocked and try to start it

On the dashboard add a game with display name Notepad test and executable notepad.exe. Leave the optional path blank. Then run Notepad explicitly from System32.

PowerShell: launch the test process 
Start-Process "$env:SystemRoot\System32\notepad.exe"
ExpectedNotepad appears and is closed cleanly (normally within about 1 second). Recent activity shows detection, close request, and a closed event. If Windows 11 opens a packaged Notepad through an alias, use the explicit System32 path above.
E.2Essential2 min

Allow play and confirm Notepad stays open

Press Allow play. Confirm the status becomes Play is allowed. Launch Notepad again.

ExpectedNotepad remains open. There is no forced close while play is allowed. The permission persists even after you close the browser.
E.3Essential2 min

Revoke play while Notepad is running

With the allowed Notepad still open, press Block play and confirm the dialog.

ExpectedThe running Notepad is asked to close and exits. The dashboard returns to Play is blocked and permission is saved as blocked.
E.4Advanced4 min

Verify the 10-second force-close fallback with timeout.exe

While play is blocked, add Console timeout test with executable timeout.exe. Open an interactive Command Prompt and run the command below. A console process has no top-level game window to receive a clean close, so this exercises the forced path. The process should disappear after about 10 seconds. Remove the timeout.exe entry afterward.

Command Prompt: start a long-lived console process 
timeout /t 300
ExpectedActivity shows that a clean close was unavailable, followed by a force-close event after the grace period. The command prompt returns when timeout.exe is terminated. If the console window itself disappears or remains is not important; verify the process is gone with Task Manager or Get-Process timeout -ErrorAction SilentlyContinue.
E.5Essential6 min

Restart the service and reboot; confirm the flag and games persist

Set a known state, for example Play is allowed with Notepad test configured. Restart the service, sign in again, then reboot the test PC and sign in once more.

PowerShell: restart the service and check state 
Restart-Service PlaygroundControl -Force
Start-Sleep -Seconds 2
(Get-Service PlaygroundControl).Status

# After reboot, open the dashboard again and sign in.
# Expected: Play is allowed and the game list are unchanged.
ExpectedThe service returns after reboot and the saved permission/game list are intact. Sessions do not survive service restart; sign in again. Play state is persistent by design and does not auto-expire.

Phase 4

LAN, authentication, and tamper boundaries

Verify the server is reachable where intended, rejects the wrong traffic, and records useful evidence. Some checks require a second device or a standard user account.

4 tests
04

Check the security boundary

Local-only endpoints, private-source networking, endpoint auth, ACLs, and standard-user limits.

S.1Essential3 min

Prove that state and health endpoints are not anonymous

On the PC, use curl.exe. State must require a session. Health must be loopback-only. A forged Host header must be rejected by the Host allowlist.

PowerShell / curl.exe security checks 
# Unauthenticated state: expected HTTP 401
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:8080/api/v1/state

# Local health: expected HTTP 200
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:8080/api/v1/health

# Forged Host header: expected HTTP 421
curl.exe -s -o NUL -w "%{http_code}`n" -H "Host: evil.example" http://127.0.0.1:8080/api/v1/bootstrap

# From a LAN device, health should be 403:
# curl -s -o NUL -w "%{http_code}\n" http://PC-LAN-IP:8080/api/v1/health
Expected401 for unauthenticated state, 200 for local health, 421 for the forged Host. LAN health is 403 while the normal LAN dashboard remains reachable.
S.2Advanced3 min

Inspect the activity log and Windows Event Log

Complete at least one permission toggle and one enforcement event first. Use an elevated PowerShell prompt because ProgramData is ACL-restricted.

PowerShell: inspect audit and service evidence 
Get-Content 'C:\ProgramData\PlaygroundControl\audit.jsonl' -Tail 15

Get-WinEvent -ProviderName PlaygroundControl -MaxEvents 15 |
  Select-Object TimeCreated, Id, LevelDisplayName, Message |
  Format-Table -Wrap

Get-Content 'C:\ProgramData\PlaygroundControl\service.log' -Tail 15
ExpectedAudit JSON lines show permission changes, game changes, login failures, and closure events with timestamps and source IPs. Event Viewer shows service start/stop and errors. No PIN, setup token, or session token appears in any log.
S.3Advanced5 min

Confirm the player account cannot stop the service or read its data

Sign in as the standard player account. Try Stop-Service PlaygroundControl and open services.msc. The operation must be refused without administrator approval. Also try reading C:\ProgramData\PlaygroundControl; access should be denied.

Standard-user PowerShell expectations 
Stop-Service PlaygroundControl
# Expected: Access is denied / Administrator permission required

Get-Content 'C:\ProgramData\PlaygroundControl\auth.json'
# Expected: Access is denied

Get-ChildItem 'C:\ProgramData\PlaygroundControl'
# Expected: Access is denied
ExpectedStandard-user attempts fail. This supports the documented threat model: a non-admin player cannot trivially stop the service or edit PIN/config data. A Windows administrator can always override the system.
S.4Advanced3 min

Inspect the firewall scope and network profile behavior

The installed rule should allow TCP 8080 only on the private profile and only from the local subnet. If your LAN is marked Public, the rule will not apply. Verify the rule's scope and that the app does not require Internet access.

PowerShell: inspect firewall scope 
$rule = Get-NetFirewallRule -DisplayName 'Playground Control'
$rule | Select-Object DisplayName, Enabled, Direction, Action, Profile
$rule | Get-NetFirewallAddressFilter | Format-List LocalAddress, RemoteAddress
$rule | Get-NetFirewallPortFilter | Format-List Protocol, LocalPort, RemotePort
Get-NetConnectionProfile | Select-Object Name, NetworkCategory
ExpectedRule enabled, inbound, allow, TCP 8080, Private profile, local-subnet scope. The computer's active LAN profile is Private. No public/Internet exposure is configured.

Phase 5

Uninstall and cleanup

This is destructive by design. It removes all settings, including the PIN and audit history. Run it last.

2 tests
!

Destructive step. Export any test report or logs you need first. If you want to keep the game list, do not uninstall until the test is complete.

05

Remove the app and verify no leftovers

The uninstaller stops the service, removes artifacts, and schedules its temporary copy for cleanup.

U.1Essential3 min

Uninstall from Windows Settings or the EXE

Use Settings > Apps > Installed apps > Playground Control > Uninstall, or run the installed EXE with --uninstall from an elevated prompt. Approve UAC and the confirmation dialog.

PowerShell: direct uninstall path 
& 'C:\Program Files\PlaygroundControl\PlaygroundControl.exe' --uninstall
ExpectedThe uninstaller stops and deletes the service, removes the firewall rule and uninstall entry, removes Program Files and ProgramData, and shows a completion dialog. A temporary uninstaller copy may remain in the user's temp folder until the next reboot.
U.2Essential2 min

Verify no service, firewall rule, program data, or ARP entry remains

Run these checks in an elevated PowerShell prompt. It is acceptable for the temp uninstaller to require one reboot to disappear.

PowerShell: post-uninstall leftovers check 
Get-Service PlaygroundControl -ErrorAction SilentlyContinue
Get-NetFirewallRule -DisplayName 'Playground Control' -ErrorAction SilentlyContinue
Test-Path 'C:\Program Files\PlaygroundControl'
Test-Path 'C:\ProgramData\PlaygroundControl'
Test-Path 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\PlaygroundControl'
Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue
ExpectedNo service, no firewall rule, both paths are False, the uninstall registry key is absent, and nothing listens on 8080. Reboot once and confirm the temporary uninstaller is cleaned up.

Troubleshooting the test run

Use these checks before treating a failure as a product defect. Localized Windows messages may differ slightly.

Reference
SymptomCheckResolution
SmartScreen says Windows protected your PC Hash must match the artifact card. The EXE is unsigned. Verify SHA-256. In a test environment choose More info > Run anyway, or sign the release first with the Makefile sign target.
Setup page did not open Service running? Port 8080 listening? Browser blocked pop-up? Run & 'C:\Program Files\PlaygroundControl\PlaygroundControl.exe' --setup from an elevated prompt. It generates a fresh local setup link.
Setup link says token is invalid or expired Setup tokens expire after 15 minutes and are single-use. Regenerate with --setup. Initial setup must be done on the PC at 127.0.0.1, not from a phone.
Phone cannot reach the dashboard Same subnet? Network profile Private? Firewall rule present? Router client isolation enabled? Use the PC IPv4 URL, set the Wi-Fi network to Private, and inspect the firewall rule. Guest Wi-Fi often isolates clients.
Browser returns 421 Misdirected Request The Host header does not match a local IP, hostname, localhost, or 127.0.0.1. Use the dashboard URL shown in Access and security, or the PC's machine name/secondary IP. Do not use an arbitrary DNS alias.
Installer says port 8080 is already in use Another web server or leftover process owns TCP 8080. Find it with Get-NetTCPConnection -LocalPort 8080, stop that program, then rerun the installer.
Notepad does not close while blocked Was the exact System32 Notepad launched? Is the configured executable exactly notepad.exe? View Recent activity. Launch "$env:SystemRoot\System32\notepad.exe" explicitly. Store/UWP apps are outside the supported guarantee.
Game runs for up to 10 seconds while blocked This is the designed clean-close grace period for a process with no responsive window. Wait for the force-close fallback. Check for a Force-closed event. Anti-cheat-protected processes may refuse termination.
Pin change or game action returns 403 Session expired, the service restarted, or the browser lost its CSRF state. Reload the dashboard and sign in again. Service restarts invalidate in-memory sessions.
PIN is forgotten The PIN cannot be recovered, only reset. Run the installed EXE with --reset-admin from an elevated prompt. Games and permission state are preserved.
Service will not start Check service status, Event Viewer, service.log, and the ProgramData ACL. Use Get-WinEvent -ProviderName PlaygroundControl. Reinstall if the service registration is missing or corrupt; uninstall first.
Uninstall is incomplete Files may be locked by a running instance; the EXE may already be gone. Reboot, then remove any remaining service/firewall rule or rerun the installer/uninstaller. The temp uninstaller is scheduled for reboot cleanup.

For developers

Automated checks and known gaps

These do not replace the Windows acceptance run, but they catch most regressions quickly on Linux or in CI.

Dev

Linux / source checkout

Run the complete local validation pipeline 
# Run these commands from the repository root.
make check
make security
go test -race ./...
make build
sha256sum dist/PlaygroundControl.exe

make check runs module verification, vet, portable tests, formatting, JavaScript syntax checking, and Windows-target vet. make security requires the documented external scanners. go test -race catches shared-state defects. make build produces the single GUI EXE.

Windows-compiled tests under Wine

Compile and execute each Windows test suite 
# Run these commands from the repository root.
for pkg in protection model store auth enforce server platform windowsapp; do
  GOOS=windows GOARCH=amd64 CGO_ENABLED=0 \
    go test -c -o "/tmp/pc-$pkg.test.exe" "./internal/$pkg"
  WINEDEBUG=-all wine "/tmp/pc-$pkg.test.exe" -test.count=1
done

The platform suite includes a real process enumeration/kill test using process creation time, IFEO guard checks, and a Notepad graceful-close test. The server suite exercises the API, cookies, setup flow, headers, and network checks.

Automated coverage

  • Game validation, path matching, and critical-process rejection
  • Config persistence, backup recovery, fail-closed defaults, and audit rotation
  • PIN hashing, setup token consumption/expiry, lockout, sessions, and PIN changes
  • Close-request / 10-second force-close state machine and cancellation rules
  • API authorization, CSRF, origin/Host checks, setup-only-loopback, and cookies
  • Mandatory Roblox image list, renamed-process path detection, and guarded toggle failure behavior
  • Windows IFEO guard set/remove in both registry views, with restoration of any pre-existing debugger
  • Windows process safety: PID-plus-creation identity and graceful WM_CLOSE

Known validation gap

Full UAC elevation, Windows SCM service installation, firewall rule application, ACL application, Add/Remove Programs, IFEO launch interception, and reboot behavior were not executable in this Linux workspace. The IFEO set/restore logic is exercised under Wine, but the actual Windows loader interception requires a real Windows 10/11 x64 acceptance run.

The EXE is currently unsigned. Signing is supported, for example:

# Set CERT_PASSWORD in your environment; never commit signing material.
make sign SIGN_CMD='signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /f cert.pfx /p "$CERT_PASSWORD"'
